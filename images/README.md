## 🖼️ 多功模式：兩套圖各有用途（2026-08-13）

這一區有兩種圖，用途與拍法都不同，**不要互相替代**：

| | 檔名 | 位置 | 拍法 | 程式怎麼放 |
|---|---|---|---|---|
| 大預覽 | `mode-{key}.jpg` | 上方那張大圖 | **情境照**，滿版構圖 | `cover`，圖檔 16:9 與框同比例所以不會裁到東西 |
| 縮圖 | `mode-{key}-thumb.jpg` | 下方五張卡 | **白底商品照**，產品置中 | `contain`，完整顯示不裁切 |

`{key}` 是 `art` / `chair` / `shelf` / `table` / `console`。

### 只準備一套也可以

**縮圖檔缺少時會自動退回**用同模式的大預覽圖，並且那一張改用 `cover`
（情境照用 `contain` 會出現大片留白）。所以最省事的做法是：

1. 先只準備 5 張情境照 `mode-{key}.jpg`
2. 之後想要白底商品照的效果，再補 5 張 `mode-{key}-thumb.jpg`

兩種狀態都測過，不會破圖。

### 白底商品照的比例

建議 **3:2**（例如 1800×1200）。縮圖框也是 3:2，比例一致就不會出現上下白邊條。
產品置中、四周留一點空間即可，程式不會裁切。

## 🎬 設計理念區的介紹影片

影片不是放檔案就會出現播放鍵，要**填連結**。位置在 `index.html` 裡標了 `▼▼▼` 的那一行：

```html
<div class="img-container ... about-media" data-video="">
```

- YouTube：直接貼 `https://youtu.be/影片ID`（分享網址後面的 `?si=...` 是追蹤碼，可以不要）
- 自己的影片檔：放進 `images/` 再寫 `images/intro.mp4`
- **留空**：播放鍵自動隱藏，不會出現點下去沒反應的按鈕

兩件注意：

1. 畫面上那句「觀看 90 秒介紹影片」是寫死的文字，影片長度變了要一起改。
2. **用檔案直接開（`file://`）時，YouTube 會拒絕嵌入並顯示「錯誤 153」**，那是瀏覽器來源限制、不是設定錯誤。
   程式已針對這種情況改成「另開 YouTube 分頁」。想在本機看到真正的頁內播放，
   在專案資料夾執行 `python -m http.server 8000`，再開 `http://localhost:8000`。

## 🎚️ 新增：首頁的「原色 ↔ 淡色」對照滑桿（2026-08-13）

首頁主視覺現在是一個**左右可拖的對照滑桿**：分割線左邊顯示**第二代（原色）**、右邊顯示**第一代（淡色）**，
拖到最右邊就是完整原色、最左邊就是完整淡色。載入時會自動從全原色滑到 62%，提示這條線可以拖。

兩色的交界**不是硬邊，是一條約 76px 寬的漸層帶**（2026-08-13 調整）。所以兩張照片的邊界不需要對到像素級，
顏色是「融合」過去的，看起來比硬切柔和很多。

**滑桿是每張圖各自獨立的**（2026-08-13 調整）：三張輪播圖各有自己的滑桿，
哪一張有淡色版，滑桿就只出現在那一張。同一時間只有你正在看的那張可以拖。

因此檔名如下（原有 3 個檔名維持為原色版，只新增 3 個淡色版）：

| 場景 | 原色版（第二代） | 淡色版（第一代） |
|---|---|---|
| 首頁輪播 01 | `hero-01.jpg` | `hero-01-pale.jpg` |
| 首頁輪播 02 | `hero-02-family.jpg` | `hero-02-family-pale.jpg` |
| 首頁輪播 03 | `hero-03.jpg` | `hero-03-pale.jpg` |

### ⚠️ 拍攝時最重要的一條規則

> **同一個場景的兩張照片，必須是同一個角度、同一個構圖、同一個取景範圍，只有產品顏色不同。**

理由：滑桿的意義是「同一個東西的兩種顏色」。如果兩張的角度或距離不一樣，拖動時看起來會像**換了一張圖**，
而不是「顏色在變」，那個互動就失去價值了。

實務做法：**腳架不要動**。同一個位置先拍第二代（原色），換上第一代（淡色）再拍一張，中間不要移動相機。
背景、光線、構圖都保持一致。

### 只有一種顏色的照片怎麼辦

**不放淡色版就好，而且可以只做其中一張。** 程式已經處理了這種情況：

某一張的 `hero-0N-pale.jpg` 讀不到時，**只有那一張**會移除淡色圖層並隱藏滑桿，
該張就單純顯示原色版，不會破圖、不會出現壞掉的分割線；**其他張的滑桿照常運作**。

所以最省事的做法是：

1. 三張都先放原色版（`hero-01.jpg`、`hero-02-family.jpg`、`hero-03.jpg`）
2. 挑**一個**最好拍的場景，腳架不動補拍一張淡色版
3. 只放那一張的 `-pale.jpg`

這樣就有對照效果，而不需要三個場景都拍兩次。之後想補其他張，再放進來滑桿就會自己出現。

## 📐 圖片準備原則

- **格式**：`.jpg` 為主（照片類）；若改用 `.png`／`.webp`，需同步修改 `index.html` 中對應的檔名
- **檔案大小**：單張建議壓在 **500KB 以內**（可用 [tinypng.com](https://tinypng.com) 或 [squoosh.app](https://squoosh.app) 壓縮），GitHub Pages 免費額度有限、也影響手機載入速度
- **比例**：務必照表裁切，網站是 `object-fit: cover` 滿版裁切，比例不對會被裁掉重點
- **檔名**：全小寫、用 `-` 連字，**不要用中文或空格**（GitHub Pages 對非 ASCII 檔名有時會出問題）

## 🔄 圖片上傳後的生效方式

```
1. 圖片放進 images/ 資料夾
2. git add images/ → git commit → git push
3. 等 1~2 分鐘 GitHub Pages 自動重新部署
4. 瀏覽器強制重新整理（Ctrl+F5）確認
```
